Events, state, and snapshots

Events are the durable record of domain changes. An event sourced actor replays its stream when activated and applies events to rebuild current in-memory state. State fields and read models are derived views; they do not replace the event stream as the write history.

Event identity

Event inherits Message, so it carries Metadata: correlation ID, user ID, device ID, message ID, and optional transaction and causation IDs. An EventEnvelope<T> adds event ID, stream, and version for downstream delivery. Those values support tracing and ordering; the serving host must still establish current caller and source authority before dispatch.

Replay

On activation, EventSourcedActor initializes and replays stored events. Event On handlers must produce the same state from the same history and should not send provider requests, notifications, or commands as a replay side effect. Store append and actor state are separate concerns: if a commit outcome is uncertain, deactivate and reconcile against the durable head before treating memory as current.

Stateful views and snapshots

EventSourcedActor<TState> and the stateful actor types provide a typed state shape. The State/, Stateful/, and Snapshots/ source areas define state and snapshot messages. Snapshot policy and storage belong to the host and provider configuration. A snapshot speeds replay only if it is verifiably tied to the preceding event history; it is not an independent source of truth.

Actor creation is a separate lifecycle concern. CreatableActor and creation command contracts distinguish an absent actor from an existing stream. Plan explicit first-write and retry behavior; do not assume that every command can create an actor.

Versioning and schema evolution

IStore.Append accepts an expected event version. A mismatch must reject the append. When event types or serialization formats evolve, keep historical payloads readable and validate a replay of old streams before deploying writers that produce the new format. The framework supplies serializer implementations, while your application owns event schema compatibility.
