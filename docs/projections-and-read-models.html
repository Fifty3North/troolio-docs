Projections and read models

Projections turn committed events into query-focused views. They run after the command's durable write boundary, so a successful command does not imply an immediately updated read model.

The handoff boundary

A selected atomic store commits required projection handoffs with participant events and completion evidence. Projection workers later consume those handoffs, apply read-model changes, and record progress. If a worker fails, the handoff remains available for recovery. The host chooses and operates the consumers; Troolio does not start a production read-side service merely because a package is installed.

The ordinary route can use inline or configured outbox dispatch. When ProjectionDispatch:Mode selects OutboxPrimary for an actor, the store must report that it atomically commits dispatch with events. The actor rejects that configuration if the store cannot meet the contract.

Read model actors

ProjectionActor and ReadModelProjectionActor<T> consume event envelopes. TroolioReadModel and ReadModelResolver are query-side building blocks. Link events can track how a read model relates to a source stream. A read-model schema is application-owned; preserve idempotent processing and version checks when workers retry.

What clients should expect

Read-side lag is normal. If an API needs read-your-write behavior, the application must design a receipt/version wait or another explicit query strategy. A client notification channel such as Server-Sent Events belongs to the host's projection integration and should not hold an accepted business command open.

Example: Query a read model

This read model has a Guid constructor for the resolver and applies the counter event. The client resolves it by ID; its value can lag behind the command. Production read models should override Authorized with their application access rule.

public sealed record CounterReadModel(Guid Id) : TroolioReadModel
{
    public int Count { get; init; }
    public CounterReadModel On(EventEnvelope<Incremented> _) =>
        this with { Count = Count + 1 };
}

public static async Task<int> ReadProjection(ITroolioClient client) =>
    (await client.Get<CounterReadModel>("d1cb4bc0-114d-4a8c-9a5e-f460784d7340")).Count;
