Testing applications

Test a Troolio application at the contract boundaries it actually deploys. A unit test can check event decisions and replay; it cannot prove store atomicity, route admission, or crash recovery.

Useful test layers

  1. Actor logic: issue commands, inspect emitted events, replay them, and verify queries. Cover duplicate creation, stale versions, and invalid transitions.
  2. Store conformance: reject a changed batch with the same operation ID, stale expected versions, stale route epochs, and deleted owners. Prove that ancillary streams, projection handoffs, and receipt commit together.
  3. Subscriber and effect recovery: crash between claim and completion, retry a provider with the same idempotency key, and verify a definitive terminal receipt.
  4. Provider integration: use real SQL Server or KurrentDB for locking, transactions, migration, credentials, and broker failover checks.
  5. Package consumer: restore the exact public package versions into an empty-cache .NET 10 project and compile a host with the adapters it actually uses.

The repository's Tests/, Troolio.Agents.Tests/, and probes/ProductionPackageConsumer/ offer examples of framework acceptance. Adapt them to application-specific actor and provider policies. See first actor, atomic commit, and recovery.
