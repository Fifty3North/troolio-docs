Core concepts

Troolio joins actor command handling to an event ledger and asynchronous read models. The application host decides which path is active.

Actors and events

Microsoft Orleans provides the virtual actor runtime. Troolio adds event-sourced actor and CQRS primitives so commands can produce durable domain events. State and read models are derived from those events rather than treated as the authoritative write record.

Selected atomic commit

On an explicitly selected command path, the framework plans a bounded causal closure of participant events in memory. A compatible atomic store must commit those events, required durable projection handoffs, and completion evidence as one transaction. Planning alone is not durable; an incomplete commit cannot be reported as success.

Choose a store whose actual transaction contract matches the full participant and handoff set for the selected route.

Projection handoffs

After commit, projection workers consume durable handoffs and update read models. This makes the read side eventually consistent. The host owns consumer operation, retries, recovery, and any client notification transport such as Server-Sent Events.

External effects

An event transaction does not make network or provider effects exactly once. Durable effect intents need provider-side idempotency keys and terminal receipts for known outcomes. Uncertain outcomes should retain the same key through recovery.

The host contract

Your serving host authenticates callers and authorizes each command against current trusted authority. It supplies source observations, ownership and lifecycle checks, route fences, retention windows, provider credentials, and recovery operations. A package reference does not enable a production route or establish application readiness.
